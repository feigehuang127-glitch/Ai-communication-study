## 二、UI/UX 优化

### 2.1 主题系统（优先级：高）

**现状：** 仅支持浅色主题，硬编码颜色值分散在各 Panel 中。

**优化方案：**
```
新增 FlatLaf 暗色主题切换
├── 全局色彩 Token 化 → 将颜色常量统一定义到 ThemeColors 类
├── 添加主题切换按钮（设置页或首页）
│   ├── 浅色：FlatLightLaf
│   ├── 暗色：FlatDarkLaf
│   └── 跟随系统（Java 17+ 可检测 OS 主题）
└── FlatLaf.properties 文件统一管理圆角、间距、滚动条样式
```

**实施要点：**
- 创建 `youxi.theme.ThemeManager` 单例类管理全局色彩
- 所有 Panel 从 `ThemeManager` 获取颜色，而非硬编码
- 主题切换时调用 `SwingUtilities.updateComponentTreeUI(frame)` 即可全局刷新

### 2.2 页面转场动画（优先级：中）

**现状：** `CardLayout.show()` 直接切换，无过渡效果。

**优化方案：**
- 添加 300ms 淡入淡出效果
- 可选：答题页面上下题之间 slide 滑动过渡
- 实现方式：`javax.swing.Timer` 驱动透明度渐变

### 2.3 响应式布局改进（优先级：低）

**现状：** `setResizable(false)`，窗口固定 520×720。

**优化方案：**
- 放开窗口缩放限制
- 使用 `ComponentListener` 监听窗口大小变化，动态调整卡片和字体大小
- 设定最小窗口尺寸 480×640

### 2.4 键盘快捷键（优先级：中）

**现状：** 纯鼠标操作。

**优化方案：**
- 答题页：数字键 1-4 选择选项，Enter 确认，Space 下一题
- 全局：Esc 返回上一页
- 使用 `InputMap` / `ActionMap` 绑定按键

## 三、游戏化机制增强

### 3.1 积分系统深化（优先级：高）

**现状：** 基础积分 + 5 级段位（青铜/白银/黄金/钻石/王者），段位阈值 0/500/2000/5000/10000。

**优化方案：**
```
积分体系升级
├── 答题得分细化
│   ├── 基础分：10 分/题（正确）
│   ├── 速度奖励：剩余时间 × 倍率（0.5秒 = 额外+5分）
│   ├── 连击奖励：连对 ≥3 题，每题额外 +2×combo 分
│   └── 全对奖励：10/10 额外 +30 分
├── 段位扩展
│   ├── 当前：5 个段位 × 1 小段
│   └── 优化：5 段位 × 3 小段（如青铜Ⅲ→青铜Ⅱ→青铜Ⅰ→白银Ⅲ...）
│       阈值重新校准：每小段 300 分，共 15 小段 = 4500 分到王者
└── 经验值（EXP）与积分分离
    ├── 积分 → 段位晋升（不可消耗）
    └── 金币 → 可消耗（用于解锁提示、跳过等道具）
```

### 3.2 成就系统（新增）（优先级：中）

**设计 12 个成就：**

| 成就名 | 图标 | 条件 |
|--------|------|------|
| 初出茅庐 | 🌱 | 完成第一场答题 |
| 学海无涯 | 📖 | 累计答对 100 题 |
| 百题斩 | ⚔️ | 累计答对 500 题 |
| 知识宝库 | 🏛️ | 累计答对 2000 题 |
| 满分传说 | ⭐ | 单场 10/10 全对 |
| 速度之星 | ⚡ | 平均答题时间 < 3 秒 |
| 连胜王者 | 🔥 | 连续答对 20 题 |
| 全科通才 | 🎓 | 6 个学科各完成一场 |
| 签到达人 | 📅 | 连续签到 7 天 |
| 错题克星 | 💪 | 消灭 50 道错题 |
| 坚如磐石 | 🛡️ | 连续登录 30 天 |
| 独孤求败 | 👑 | 达到王者段位 |

**技术方案：**
- 新建 `achievements` 表（id, name, description, icon, condition_type, threshold）
- 新建 `user_achievements` 表（user_id, achievement_id, unlocked_at）
- `AchievementChecker` 服务类，每次答题结束/签到/错题移除后触发检查

### 3.3 排行榜系统（新增）（优先级：中）

**设计 3 个排行榜：**
1. **总积分榜** — 所有用户按总积分排名
2. **周榜** — 本周获得的积分排名（每周一重置）
3. **学科榜** — 每个学科的答题总数排名

**技术方案：**
- 新建 `leaderboard` 视图或查询
- 在首页或积分页以列表形式展示 Top 20
- 当前用户排名高亮

### 3.4 每日挑战（新增）（优先级：低）

- 每天生成 5 道随机题的"每日挑战"
- 完成后额外奖励积分（如 +20 分）
- 在首页显示"今日挑战"入口

## 四、答题体验提升

### 4.1 音效系统（新增）（优先级：中）

**需要 6 种音效：**

| 音效 | 触发时机 | 风格 |
|------|---------|------|
| click | 点击按钮 | 清脆短促 |
| correct | 答对 | 上升音阶 |
| wrong | 答错 | 低沉闷响 |
| combo | 连击 ≥3 | 激昂短乐 |
| timeout | 超时 | 滴答警告 |
| victory | 通关/满分 | 庆祝乐章 |

**技术方案：**
- Java 内置 `javax.sound.sampled` API（无需第三方库）
- 创建 `SoundManager` 单例，预加载所有音效到内存
- WAV 格式（Java 原生支持），每个文件 < 100KB

### 4.2 动画反馈（优先级：中）

| 动画 | 实现方式 |
|------|---------|
| 选项选中脉冲 | `javax.swing.Timer` 驱动 scale 变化 |
| 正确答案绿色闪烁 | Timer 交替背景色 |
| 错误答案红色抖动 | Timer 驱动 x 轴偏移（shake） |
| 分数弹出 +N | 临时 JLabel 上浮消失 |
| 进度条平滑过渡 | 自定义 ProgressBarUI |

### 4.3 答题流程优化（优先级：中）

**现状问题：**
- 答完题后需要点"确认"按钮再点"下一题"
- 判断题也需要确认

**优化方案：**
- 单选题：点击选项后 0.8 秒自动确认并进入下一题（可配置开关）
- 多选题：点击"确认提交"按钮（保持不变）
- 判断题：点击选项即确认（简化操作）
- 添加"跳过"按钮（不扣分，但计为未答）

### 4.4 难度自适应（优先级：低）

**方案：**
- 根据用户近期答题正确率动态调整出题难度
- 正确率 > 80%：提升难度等级
- 正确率 < 50%：降低难度等级
- 难度等级映射到 `questions.difficulty`（1-5）

## 五、性能优化

### 5.1 数据预加载 & 缓存（优先级：高）

**现状问题：**
- 每次进入学科选择页都查询数据库
- 答题时逐题从数据库读取

**优化方案：**

```
缓存架构
├── 问题缓存（Caffeine）
│   ├── 启动时预加载全部 1623 题到内存
│   ├── 按学科建立索引 Map<String, List<Question>>
│   ├── 内存占用估算：1623 题 × ~1KB/题 ≈ 1.6MB（可忽略）
│   └── 过期策略：手动刷新（仅在导入新题后）
├── 用户数据缓存
│   ├── 登录时加载用户信息到 UserSession 单例
│   ├── 积分变化时同时更新内存 + 数据库
│   └── 签到状态缓存（避免每次首页刷新查 DB）
└── 连接池优化
    ├── 当前 HikariCP 已是最佳选择
    └── 建议配置：maximumPoolSize=5, minimumIdle=2
```

### 5.2 启动速度优化（优先级：中）

**优化措施：**
- 延迟加载：MainFrame 先显示，背景图异步加载
- 数据库预热：连接池在后台线程初始化
- 非关键 Panel 懒加载：首次 `showPanel()` 时才创建实例
- 当前做法（编译期构造所有 Panel）改为懒加载模式

### 5.3 数据库查询优化（优先级：中）

**建议添加索引：**
```sql
-- 已有（推测基于主键）
-- 建议补充：
CREATE INDEX idx_questions_category ON questions(category);
CREATE INDEX idx_questions_type ON questions(type);
CREATE INDEX idx_wrong_questions_user ON wrong_questions(user_id);
CREATE INDEX idx_game_history_user ON game_history(user_id, created_at);
```

## 六、架构优化

### 6.1 配置外部化（优先级：高）

**现状：** 数据库连接、API Key 等硬编码在代码中。

**优化方案：**
- 创建 `config.properties` 文件
- 可配置项：
  - 数据库 URL / 用户名 / 密码
  - 每场题数（当前 10）
  - 每题限时（当前 10 秒）
  - 连击阈值（当前 5 题）
  - API Key 和 API URL

### 6.2 MVC 分离重构（优先级：中）

**现状：** Panel 层混合了视图逻辑和业务逻辑（如 GamePanel 直接调用 DAO）。

**优化方案：**
```
youxi
├── model/          # 数据模型（不变）
├── view/           # 纯视图层
│   ├── panel/      # 所有 JPanel 子类
│   └── component/  # 可复用组件（徽章、卡片等）
├── controller/     # 控制器（新增）
│   └── GameController.java  # 答题流程控制
├── service/        # 业务逻辑（不变）
├── dao/            # 数据访问（不变）
└── util/           # 工具类（不变）
```

### 6.3 嵌入式数据库迁移准备（优先级：低）

**当前：** MySQL（用户选择暂保留）

**未来方案：**
- 目标：H2 Database（嵌入式，无需安装 MySQL）
- 迁移步骤：
  1. 导出 MySQL 数据为 SQL 脚本
  2. 适配 SQL 语法差异（如 `AUTO_INCREMENT` → H2 语法）
  3. 替换 `DBHelper` 连接逻辑
  4. 打包为单一 JAR 可分发
